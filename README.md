# ⚡ Grafic_Lib

Интерактивный граф связей для структурированных учебных материалов. Каждое понятие, теорема или определение живёт на отдельной HTML-карточке; рёбра графа показывают, как эти понятия связаны между собой. Граф можно листать, масштабировать и искать по нему — прямо в браузере.

## Идея и назначение

Обычные конспекты и учебники показывают материал линейно — от раздела к разделу. Но математические (и не только) понятия устроены иначе: они образуют сеть. Теорема опирается на лемму, лемма использует определение из другой главы, определение связано с аксиомой из совсем другого раздела.

Этот проект визуализирует такую сеть в виде интерактивного графа:

- каждый узел — отдельная карточка с текстом (определение, теорема, пример);
- каждое ребро — смысловая связь между карточками;
- цвет узлов и рёбер отражает принадлежность к разделу;
- граф можно исследовать руками: зумить, листать, искать нужное понятие, раскрывать карточку и переходить по связям.

Проект не привязан к математике — подойдёт для любой предметной области, которую можно описать иерархическим деревом тем с перекрёстными связями.

## Как это работает

Данные проходят через пайплайн из пяти шагов:

```
terms.json
    │
    ▼
[1] coords ──► cards_positions.json   (координаты узлов, цвета разделов)
                cards_edges.json       (структурные рёбра дерева)
    │
    ▼
[2] gen ─────► cards/<id>.html        (HTML-карточки, текст генерирует DeepSeek API)
                cards.db · таблица cards
    │
    ▼
[3] colors ──► cards.db · section_color, root_section
    │
    ▼
[4] sync ────► cards.db · cords_x, cords_y
    │
    ▼
[5] arrows ──► cards.db · таблица arrows
    │
    ▼
server.py ───► REST API на :8000
    │
    ▼
браузер ─────► граф
```

Сервер при каждом запросе отдаёт карточки и стрелки из SQLite; фронтенд рендерит их на Canvas + SVG поверх виртуального пространства 10 000 × 10 000 px. Видимые узлы и рёбра отрисовываются только внутри текущего вьюпорта — это позволяет без лагов работать с сотнями и тысячами карточек.

## Стек технологий

| Слой | Технология | Зачем |

## Быстрый старт

### 1. Установить зависимости

```bash
pip install fastapi uvicorn openai
```

### 2. Подготовить дерево тем

Создайте файл `terms.json` с иерархическим деревом тем (подробнее — в разделе [Формат terms.json](#формат-входных-данных--termsjson)).

### 3. Задать API-ключ

```bash
# Linux / macOS
export DEEPSEEK_API_KEY="sk-ваш-ключ"

# Windows (PowerShell)
$env:DEEPSEEK_API_KEY = "sk-ваш-ключ"
```

Или вставьте ключ прямо в `pipeline.py` в переменную `API_KEY` в начале файла. Если ключ не задан, шаг генерации текста будет пропущен, а карточки останутся с заглушками.

### 4. Запустить пайплайн

```bash
python pipeline.py
```

Пайплайн последовательно вычислит координаты, сгенерирует карточки, запишет цвета и стрелки в БД. На несколько сотен карточек уходит 5–15 минут в зависимости от скорости API.

### 5. Запустить сервер

```bash
python server.py
```

Открыть в браузере: `http://localhost:8000`

## Генерация данных — pipeline.py

`pipeline.py` объединяет все вспомогательные скрипты в один файл с пятью последовательными шагами. Каждый шаг можно запустить отдельно, что удобно при повторной генерации части данных.

### Шаги пайплайна

**`coords`** — вычисление координат узлов. Читает `terms.json`, назначает каждому узлу позицию (x, y) в диапазоне 0–100 % мирового пространства и цвет раздела. Алгоритм использует спираль Фибоначчи внутри угловых секторов. Результат сохраняется в `cards_positions.json` и `cards_edges.json`.

**`gen`** — генерация HTML-карточек. Для каждой темы из дерева строит связи (chapter / usein / teorems) программно по структуре дерева, затем запрашивает у DeepSeek API только чистый текст (preview + основной текст). HTML-структура, хлебные крошки и ссылки между карточками собираются программно без участия API — это ускоряет генерацию и делает структуру предсказуемой. Уже созданные карточки пропускаются, поэтому генерацию можно прерывать и продолжать. Прогресс сохраняется в `generation_progress.json`.

**`colors`** — запись цветов в БД. Добавляет колонки `section_color` и `root_section` в таблицу `cards` (если их ещё нет) и заполняет их из `cards_positions.json`. Также переписывает таблицу `edges`.

**`sync`** — синхронизация координат. Обновляет `cords_x` / `cords_y` в таблице `cards` из `cards_positions.json`. Если карточки ещё нет в БД — создаёт запись с минимальными полями.

**`arrows`** — генерация стрелок. Создаёт и наполняет таблицу `arrows`: сначала добавляет иерархические рёбра (раздел → прямые потомки), затем рёбра из полей `teorems` / `usein` / `chapter` каждой карточки. Цвет стрелки — цвет раздела источника; при межсекционных связях цвет смешивается из цветов обоих разделов в пространстве HSL.

### Команды

```bash
# Полный цикл (все 5 шагов по порядку)
python pipeline.py

# Начать с шага colors и выполнить все последующие
python pipeline.py --from colors

# Выполнить только один конкретный шаг
python pipeline.py --only arrows

# Доступные значения для --from и --only:
#   coords | gen | colors | sync | arrows
```

### Типичные сценарии

| Ситуация | Команда |
|----------|---------|
| Первый запуск, всё с нуля | `python pipeline.py` |
| Добавили новые темы в `terms.json` | `python pipeline.py` (существующие карточки пропустятся) |
| Изменили цвета разделов в `pipeline.py` | `python pipeline.py --from colors` |
| Вручную изменили координаты в `cards_positions.json` | `python pipeline.py --from sync` |
| Пересчитать только стрелки | `python pipeline.py --only arrows` |
| Перегенерировать конкретную карточку | Удалить `cards/<id>.html` и строку из `cards.db`, затем `python pipeline.py --only gen` |

### Мониторинг генерации

Во время шага `gen` выводится прогресс-бар:

```
🔄 Генерация [████████████░░░░░░░░░░░░░░░░] 43.2% (148/342) ⏱06:14 ⚡24.1т/м 🪙84,320 💵$0.023 ✅ #148 Теорема Виета
```

Поля: процент, позиция/всего, ETA, скорость (карточек в минуту), суммарные токены, примерная стоимость, статус текущей карточки.

## Формат входных данных — terms.json

`terms.json` — иерархическое дерево тем. Корень — произвольное название предметной области, дальше — вложенные разделы и листья-темы.

```json
{
  "Математика": {
    "Алгебра": {
      "Многочлены": [
        "Степень многочлена",
        "Деление многочленов",
        "Теорема Виета"
      ],
      "Уравнения": [
        "Линейные уравнения",
        "Квадратные уравнения",
        "Системы уравнений"
      ]
    },
    "Геометрия": {
      "Планиметрия": [
        "Теорема Пифагора",
        "Площадь треугольника"
      ]
    }
  }
}
```

Правила структуры:

- Вложенность не ограничена, оптимально 2–4 уровня.
- Объекты `{}` — разделы (узлы-заголовки на графе), массивы `[]` — конечные темы (карточки с текстом).
- Названия должны быть уникальными в пределах всего дерева — они используются как ключи при построении связей.
- Корневой ключ (`"Математика"` в примере) можно заменить на любое название; скрипт автоматически использует его как корень.

Связи между карточками строятся автоматически по структуре дерева:

- `chapter` — непосредственный родительский раздел;
- `usein` — все дочерние темы, вложенные глубже по тому же пути;
- `teorems` — соседи по разделу (одинаковый родитель) плюс темы из других разделов с совпадающими словами в названии.

## REST API

Сервер поднимается на `http://localhost:8000`.

| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/` | Отдаёт `index.html` |
| `GET` | `/api/topics` | Список всех тем с метаданными |
| `GET` | `/api/{slug}/cards` | Все карточки темы с координатами и связями |
| `GET` | `/api/{slug}/arrows` | Все стрелки темы |
| `GET` | `/topics/{slug}/cards/{id}.html` | HTML-страница карточки |

### Пример ответа `/api/topics`

```json
[
  {
    "slug": "math",
    "name": "Математика",
    "cards": 342,
    "arrows": 1205,
    "created_at": "2025-01-10T14:32:00"
  }
]
```

### Пример ответа `/api/{slug}/cards`

```json
[
  {
    "id": 42,
    "name": "Теорема Виета",
    "cords": {"x": 63.4, "y": 41.7},
    "teorems": [38, 45],
    "usein": [],
    "chapter": [12],
    "html_path": "/topics/math/cards/42.html",
    "preview": "Теорема, связывающая коэффициенты многочлена с его корнями...",
    "section_color": "#3498db",
    "root_section": "Алгебра"
  }
]
```

## Схема базы данных

### Таблица `cards`

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | INTEGER PK | Уникальный идентификатор; совпадает с порядком обхода дерева |
| `name` | TEXT | Название темы |
| `cords_x` | REAL | Позиция по горизонтали, 0–100 % |
| `cords_y` | REAL | Позиция по вертикали, 0–100 % |
| `teorems` | TEXT | ID связанных тем (соседи + перекрёстные), через запятую |
| `usein` | TEXT | ID дочерних тем, через запятую |
| `chapter` | TEXT | ID родительского раздела, через запятую |
| `section_color` | TEXT | Цвет раздела `#rrggbb` |
| `root_section` | TEXT | Название корневого раздела (первый уровень дерева) |

### Таблица `arrows`

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | INTEGER PK | |
| `source_id` | INTEGER FK | Откуда идёт стрелка |
| `target_id` | INTEGER FK | Куда идёт стрелка |
| `x1`, `y1` | REAL | Координаты начала, 0–100 % |
| `x2`, `y2` | REAL | Координаты конца, 0–100 % |
| `color` | TEXT | Цвет стрелки `#rrggbb` |
| `type` | TEXT | Тип: `hierarchy` / `same_section` / `cross_section` |
| `source_links` | TEXT | Все связи источника, через запятую |
| `target_links` | TEXT | Все связи цели, через запятую |

### Типы стрелок

- `hierarchy` — иерархические рёбра дерева: раздел → прямой потомок. Цвет раздела-источника.
- `same_section` — связь между двумя карточками внутри одного корневого раздела. Цвет раздела.
- `cross_section` — связь между карточками из разных разделов. Цвет смешивается из цветов обоих разделов в пространстве HSL.

## Интерфейс

### Навигация по графу

Граф существует в виртуальном пространстве 10 000 × 10 000 px; координаты карточек хранятся в процентах от этого пространства. Фронтенд рендерит только узлы и рёбра внутри текущего вьюпорта плюс буферная зона 600 px — это обеспечивает плавность при больших графах.

| Действие | Результат |
|----------|-----------|
| Перетащить фон мышью | Панорамирование |
| Колесо мыши | Зум от 5 % до 300 % с центрированием на курсоре |
| Кнопки `+` / `−` | Зум шагами |
| Кнопка `⟲` | Сброс к оптимальному зуму для текущего числа карточек |

Оптимальный зум при сбросе подбирается автоматически: >500 карточек → 18 %, >200 → 35 %, >50 → 60 %, меньше → 100 %.

### Карточки

Каждый узел на графе — карточка в одном из двух состояний:

**Компактное** (по умолчанию): отображает название и ID, занимает ~150 × 50 px. При наведении немного осветляется.

**Раскрытое** (по клику): карточка расширяется до 220 px, граф центрируется на ней. Показывается превью-текст и список связанных карточек. Повторный клик открывает полную HTML-страницу в новой вкладке.

При раскрытой карточке обычные рёбра скрываются; вместо них SVG-линиями подсвечиваются только рёбра этой карточки — кликабельные, с hover-эффектом. Клик по стрелке переходит к карточке на другом конце.

### Поиск

Поиск работает по названию и тексту превью одновременно с задержкой 200 мс. Результаты появляются в выпадающем списке; навигация — стрелками клавиатуры, выбор — Enter или клик. При выборе граф центрируется на найденной карточке и раскрывает её.

Опция **«скрыть остальные»** делает все несовпадающие карточки прозрачными — удобно при работе с плотным графом.

### Переключатель тем

В левой части шапки расположен дропдаун со списком всех доступных тем. При переключении граф полностью перезагружается без обновления страницы: зум и позиция сбрасываются, кэш DOM очищается.

> ⚠️ **Фильтрация по типу связи временно отключена.** Кнопки `теоремы / usein / chapter` скрыты из интерфейса, логика фильтрации закомментирована в `script.js`. Функциональность будет переработана в следующих версиях.

## Формат HTML-карточки

Каждая карточка — самостоятельный HTML-файл в папке `cards/`. Сервер отдаёт их как статику по пути `/topics/{slug}/cards/{id}.html`.

Структура файла, которую генерирует `pipeline.py`:

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>#42 — Теорема Виета</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <article id="42" class="card-full">

    <div class="card-id">карточка #42</div>
    <h1 class="card-title">Теорема Виета</h1>

    <div class="breadcrumbs">
      <a href="/cards/3.html">Алгебра</a> →
      <a href="/cards/12.html">Многочлены</a> →
      <span>Теорема Виета</span>
    </div>

    <!-- Этот блок читается сервером для превью на графе -->
    <section type="pref">
      <div class="pref-text">
        Теорема, связывающая коэффициенты многочлена с его корнями...
      </div>
    </section>

    <section type="link">
      <div class="links-list">
        <a href="/cards/38.html" class="card-link">Степень многочлена</a>
      </div>
    </section>

    <section type="main">
      <div class="main-text">
        Для квадратного трёхчлена ax^2 + bx + c с корнями x₁ и x₂...
      </div>
    </section>

    <a href="/" class="back-link">← назад к графу</a>
  </article>
</body>
</html>
```

Ключевой момент — секция `<section type="pref">`. Сервер извлекает из неё текст (без HTML-тегов, первые 200 символов) и возвращает как поле `preview`. Именно этот текст показывается в раскрытой карточке на графе и участвует в поиске. Если секция отсутствует, превью берётся из названия карточки.

Карточки можно редактировать вручную — сервер читает только `<section type="pref">`, остальная структура произвольна.

## Несколько тем

Сервер поддерживает несколько независимых тем через реестр `topics/registry.json`. Каждая тема имеет свою БД и папку карточек.

### Создание новой темы

```bash
python create_topic.py
```

## Алгоритм расположения узлов

Позиции карточек вычисляются детерминировано — при одинаковом `terms.json` результат всегда одинаков.

**Корневые разделы** располагаются по окружности вокруг центра (50, 50). Угловой сектор каждого раздела пропорционален числу карточек в нём. Радиус — обратно пропорционален размеру раздела: меньшие разделы ближе к центру.

**Дочерние узлы** внутри каждого сектора распределяются спиралью Фибоначчи: шаг угла = 2π / φ², где φ — золотое сечение. Радиус растёт пропорционально √(порядковый номер), что даёт равномерное заполнение без сгустков в центре. Подразделы (не листья) притягиваются к центральной оси сектора с коэффициентом 0.4, чтобы визуально отделяться от конечных тем.

**Цвета разделов** заданы в `SECTION_COLORS` в `pipeline.py`. Для разделов не из этого списка цвет берётся из `FALLBACK_COLORS` по хешу имени — цвет стабилен при повторных запусках. Цвет стрелки между разделами вычисляется как среднее двух цветов в пространстве HSL по кратчайшей дуге.
